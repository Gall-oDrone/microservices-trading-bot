# Prometheus Alert Rules

Alert rule files in this directory are loaded by Prometheus via `rule_files: - "rules/*.yml"` in `../prometheus.yml`.

## trading-alerts.yml

- **ServiceDown** – Any target `up == 0` for 1m (critical).
- **BalanceLastSuccessTimestampStale** – Bitso balance not refreshed in 5m (critical, trading-engine).
- **TradingEngineOrdersFailedRateHigh** – Order failure rate > 0.5/s over 5m (critical).
- **TradingEngineNotRunning** – Trading-engine up but `engine_state != 2` for 5m (warning).
- **TradingEngineHealthCheckFailuresHigh** – Health check failures > 5 in 15m (warning).
- **TradingEngineHighErrorRate** – HTTP 5xx rate > 0.1/s (critical).
- **APIRateLimitExceeded** – Bitso API rate limit metric > 0 (warning).
- **HighOrderExecutionLatency** – p95 order execution latency > 5s (warning).
- **LowAvailableBalance** – `bitso_available_balance` < 1000 (critical).

Severity and routing (e.g. to Alertmanager and on-call) should be configured in Alertmanager.

## trading-risk-alerts.yml (2026-10-08)

Trading-risk operations alerts (kill switch, limit breaches and utilization, fail-closed blocks,
execution quality, OMS-exchange reconciliation). Every alert has a `runbook_url` into
[`docs/runbooks/TRADING-RISK-ALERTS.md`](../../../docs/runbooks/TRADING-RISK-ALERTS.md) and a `team`
label (`risk` or `trading`). Severity: `critical` pages, `warning` is reviewed the same trading day.

- Unit tests: `promtool test rules monitoring/prometheus/tests/trading-risk-alerts.test.yml`
  (kept outside `rules/` so the `rules/*.yml` glob does not load them).
- k8s copy: `k8s/monitoring/trading-risk-rules.yaml` is generated by
  `scripts/sync-prometheus-rules.sh`; edit the source here and re-run it.
- CI job `monitoring-rules` (`.github/workflows/operator-ui.yml`) runs `promtool check rules`, the
  unit tests and the sync check.
- Dashboard: `monitoring/grafana/dashboards/domain/trading-risk-operations.json`.

## trading-slo-rules.yml (2026-10-20, generated)

Trading-operations SLOs (frontend plan §6.4.15 / §11 q4): recording rules for eight 30-day SLOs
(error ratio over 5m..30d, burn rate, SLI, budget remaining) and multi-window burn-rate alerts.
**Generated** by `scripts/gen-slo.py` from [`../slo/trading-slos.yaml`](../slo/trading-slos.yaml)
together with the dashboard `monitoring/grafana/dashboards/domain/trading-slo.json`; edit the spec,
not this file (CI runs `scripts/gen-slo.py --check`).

- Event SLIs (orders, decisions) are gated on `slo:min_events:*`: this platform trades a few times
  a day, so one slow order must not page. Time SLIs (freshness, kill-switch readiness) page normally.
- Unit tests: `promtool test rules monitoring/prometheus/tests/trading-slo-rules.test.yml`.
- k8s copy: `k8s/monitoring/trading-slo-rules.yaml` by `scripts/sync-prometheus-rules.sh`.
- Runbook: [`docs/runbooks/TRADING-SLO.md`](../../../docs/runbooks/TRADING-SLO.md).
